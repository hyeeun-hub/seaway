# calendar-chatbot-skill

## 목적
분석/검수 결과를 바탕으로 확정 계약과 예정 계약 관련 정보를 실제로 정리하고, 회수 캘린더 관리와 챗봇 응답, 실행 요약/상태를 준비한다.  
사용자가 결과를 보고 다음에 무엇을 할지 판단할 수 있게, 상태와 요약 정보를 최종 결과에 포함되게 한다.

## 언제 실행하나
- 분석/검수 결과가 준비되면 실행한다.
- 확정 계약 데이터를 반영해야 할 때 실행한다.
- 예정 계약 데이터를 관리해야 할 때 실행한다.
- 챗봇 질의가 들어왔을 때 실행한다.
- 사용자 캘린더 수정 입력이 있을 때 실행한다.

## 입력
- 확정 계약 데이터
- 예정 계약 데이터
- 분석/검수 결과
- 챗봇 질의
- 사용자 캘린더 수정 입력
- 필요 시 프로젝트별 손익, 월별 손익, 기준 정보

## 처리
- 확정 계약 데이터를 반영해 회수 캘린더 데이터를 정리한다.
- 예정 계약 데이터를 관리해, 예정 상태의 계약/회수 예정 정보를 볼 수 있게 한다.
- 캘린더 뷰와 목록 뷰에서 쓸 정보를 준비한다.
  - 언제 얼마가 회수/발생하는지
  - 어떤 프로젝트/계약과 연결되는지
  - 확정인지 예정인지
  - 참고할 분석/검수 결과가 있는지
- 챗봇 질의를 받아 응답할 수 있게 준비한다.
  - 프로젝트별 손익, 월별 손익, 검수 상태, 캘린더 정보 등을 바탕으로 답변
  - 질의에 필요한 범위만 정리해 응답
- 실행 요약/상태를 정리한다.
  - 현재까지 진행된 단계
  - 확정된 결과
  - 확인 필요한 사항
  - 다음 액션에 참고할 정보

## 출력
- 회수 캘린더 데이터
- 캘린더 뷰/목록 뷰용 정보
- 챗봇 응답
- 실행 요약/상태

## 산출물
- 회수 캘린더 데이터
- 캘린더/목록 뷰 정보
- 챗봇 응답
- 실행 요약/상태

## 실행 조건
- 분석/검수 결과 또는 계약 관련 데이터가 있어야 실행한다.
- 챗봇 질의가 있으면 그에 맞는 범위만 응답한다.
- 캘린더 수정은 사용자 입력이 있을 때만 반영한다.
- 결과가 아직 충분하지 않으면 “없음”이나 “추후 반영 예정”처럼 그대로 끝내지 말고, 현재 상태와 필요한 후속 정보를 함께 남긴다.

## 결과 전달 방식
- 이 스킬의 결과는 다음 단계로 자동으로 넘겨진다.
- 사용자는 중간 캘린더/챗봇 처리 과정을 따로 보지 않고, 최종 결과에서 회수 캘린더, 실행 요약, 챗봇 응답, 상태를 확인할 수 있게 한다.
- 확정/예정 상태와 분석/검수 결과의 연결을 유지한다.

## 재사용성
- 특정 일정 하나를 보는 용도가 아니라, 확정 계약/예정 계약/회수 캘린더/챗봇 응답/실행 요약을 공통으로 다루는 스킬로 쓴다.
- 캘린더 뷰와 목록 뷰를 분리해 준비하므로, 이후 화면 구성이 달라져도 재사용하기 쉽게 한다.
- 챗봇 응답은 질의 유형에 따라 필요한 데이터를 조합하는 방식으로 재사용 가능하게 만든다.

## 비고
- 이 스킬은 계약/회수 흐름을 직접 실행하는 역할보다, 그 상태를 정리하고 조회/응답/요약으로 제공하는 역할에 가깝다.
- 확정 계약 반영과 예정 계약 관리는 분석/검수 결과와 이어져야 하므로, 기준 정보와 시점을 함께 남긴다.
- 자동 검사/검증에서 이상 소견이 있으면, 그 내용도 실행 요약/상태에 반영될 수 있게 한다.

## 범위

### 처리하는 것
- 거래 레코드의 `settle_date` / `settle_method`로 회수 캘린더 데이터 구성
- `settle_date`와 오늘 날짜 비교로 확정/예정 판정
- 캘린더 뷰 / 목록 뷰용 정보 준비
- 챗봇 질의에 대한 응답 구성
- 실행 요약/상태 정리

### 처리하지 않는 것
- **`비고` 열 파싱** → analyze-skill이 `settle_date`로 넘겨준다
- **손익 계산, 리포트 생성** → analyze / query-export
- **캘린더 값 자동 변경.** 사용자 수정 입력이 있을 때만 반영한다
- **질의 범위를 넘는 정보 추가.** 묻지 않은 내용을 덧붙이지 않는다
- **실제 회수 처리, 알림 발송, 외부 캘린더 연동**

### 단일 기능 관련 참고
이 스킬은 캘린더·챗봇·실행 요약 3개를 담당하므로 단일 기능 기준으로는 경계가 넓다.
셋 모두 "분석/검수 결과를 사용자 확인용 상태 정보로 바꾸는" 동일 목적을 공유하고 같은 입력을 쓰기 때문에 한 스킬로 둔다.
캘린더 규칙이 복잡해지거나 챗봇이 다중 턴으로 확장되면 `calendar-skill` / `chatbot-skill`로 분리하는 것이 맞다.

### 출력 (챗봇 응답 예)

```
질의: "도두항 현장 손익 어때?"
응답: 2026도두항부잔교설치공사는 매출 117,330,000원, 매입 115,340,498원으로
      손익 1,989,502원(마진율 1.7%)입니다. 매출이 발생한 7개 현장 중, 마진 0%인
      통과거래(창조이엔지)를 빼면 마진율이 가장 낮습니다.
      회수는 2026-03-26 57,330,000원, 2026-05-08 60,000,000원 2건 모두 완료됐습니다.
      단, 사람 확인 필요 57건이 미확정이므로 확정 후 수치가 변동될 수 있습니다.

질의: "2월에 왜 매출이 없어?"
응답: 2026년 2월은 세금계산서 발행 건이 없어 매출이 0원입니다. 데이터 누락이 아닙니다.
      2월 매입은 92,578,174원 정상 반영돼 있어 해당 월은 -92,578,174원 적자로 집계됩니다.
```

### 출력 (실행 요약/상태)

```
진행 단계: file-input → analyze → classify → query-export → calendar-chatbot 완료
확정된 결과: 거래 869건 누적(자동 처리 808건 확정 ※예시값), 5개월 손익 집계, 프로젝트 22건
확인 필요:   검수 57건 미확정, 보류 4건(2025년 매출 데이터 미유입)
다음 액션:   검수 목록에서 57건 확정 → 재실행 시 프로젝트별 손익 재생성
```

진행 표시: `캘린더/요약 완료 — 회수 확정 11건 553,180,106원`

## 성공 기준

- [ ] 매출 11건 전부가 회수 캘린더에 오른다(누락 없음)
- [ ] 각 항목에 `settle_date`, 프로젝트, 금액, 수단, 확정/예정 상태가 있다
- [ ] `settle_date`가 없는 매입 52건이 캘린더에서 제외되고, 제외 사유가 남는다
- [ ] 확정/예정 판정이 오늘 날짜 기준으로 계산된다(하드코딩된 상태값 없음)
- [ ] 회수 금액 합계가 매출 합계 553,180,106원과 일치한다(표의 행 합계로 검산 가능해야 한다)
- [ ] 챗봇 응답이 미확정 검수 건의 존재를 알린다
- [ ] 챗봇 응답에 질의 범위를 벗어난 내용이 없다
- [ ] 실행 요약에 진행 단계 / 확정 결과 / 확인 필요 / 다음 액션 4개 항목이 모두 있다
