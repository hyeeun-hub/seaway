# verify-skill

## 목적
ERP Flow의 각 단계 이후와 최종 결과 생성 후에 자동 검사를 실제로 수행한다.  
파일 상태, 분석 정합성, 검수 누락 의심, 결과 불일치 등을 점검하고, 이상이 있으면 이상 항목·실패/이상 원인·상태 요약·재시도/안내 필요 여부를 남긴다.  
이상이 발견되면 결과를 그대로 끝내지 않고, 검수/분류 단계에서 처리할 수 있게 연결한다.

## 언제 실행하나
- 파일 접수 후
- 분석/계산 후
- 검수/분류 후
- 결과 생성/조회 후
- 최종 결과 생성 후
- 즉, 각 단계 종료 시점과 최종 결과 시점마다 실행한다.

## 입력
- 파일 정보
- 파일 상태
- 분석 결과
- 검수 결과
- 최종 결과
- 생성 시점/기준 정보
- 필요 시 이전 단계 검사 결과

## 처리
### 1) 파일 접수 단계 검사
- 파일이 있는지, 읽을 수 있는지 확인한다.
- 파일이 비어 있지 않은지 확인한다.
- 데이터 시트/데이터행이 있는지 확인한다.
- 필수 열이 있는지 확인한다.
  - 예: 거래일자, 금액, 프로젝트/현장 등
- 같은 파일이 짧은 간격 안에 다시 들어왔는지 등 중복 접수 의심 여부를 확인한다.
- 파일 상태 이상이 있으면 접수 이상 항목으로 남긴다.

### 2) 분석/계산 단계 검사
- 거래일자, 금액, 프로젝트/현장 등의 형식 이상을 확인한다.
- 날짜가 빠진 행, 금액이 숫자가 아닌 행 등 파싱/정규화 이상을 확인한다.
- 프로젝트 매칭이 지나치게 많이 누락된 경우가 있는지 확인한다.
- 월별 집계에서 합계와 세부 합이 어긋나는 경우가 있는지 확인한다.
- 일반관리비 분류에서 분류 불가/보류 항목이 과도하게 많은지 확인한다.
- 같은 월 데이터가 나중에 추가될 때 중복 제외가 제대로 동작할 수 있는지 확인한다.
- 분석 이상이 있으면 분석 이상 항목으로 남긴다.

### 3) 검수/분류 단계 검사
- 검수 대상 목록이 지나치게 많이 쌓였는지 확인한다.
- 같은 문제 유형이 반복되는데 규칙 처리로 빠지지 않는지 확인한다.
- 확정/제외/수정 결과가 서로 충돌할 가능성이 있는지 확인한다.
- 사람 확인이 필요한 건이 처리되지 않고 남아 있는지 확인한다.
- 검수 이상이 있으면 검수 누락 의심 또는 검수 이상 항목으로 남긴다.

### 4) 결과 생성/조회 단계 검사
- 조회 조건 대비 결과가 비어 있는데, 정말 데이터가 없는지 아니면 처리 중인지 구분 가능하게 확인한다.
- 월간 리포트의 기준 월과 실제 반영 데이터가 어긋나지 않았는지 확인한다.
- 프로젝트별/월별 결과가 분석/검수 결과와 일관되는지 확인한다.
- 결과 생성 이상이 있으면 결과 불일치 또는 결과 이상 항목으로 남긴다.

### 5) 캘린더/챗봇/요약 단계 검사
- 확정 계약/예정 계약 정보가 분석/검수 결과와 연결되는지 확인한다.
- 실행 요약/상태에 필요한 정보가 비어 있지 않은지 확인한다.
- 챗봇 응답이 현재 상태를 왜곡하지 않게 정리됐는지 확인한다.

### 6) 최종 무결성 검사
- 결승선 데이터의 필수 항목이 비어 있지 않은지 확인한다.
- 단계별 결과가 앞뒤가 맞는지 확인한다.
- 이전 검사에서 남긴 이상 항목이 최종 결과에 제대로 반영됐는지 확인한다.
- 최종 결과에 이상 항목이 남아 있으면, 그 원인과 조치 필요 여부를 함께 남긴다.

## 자동 검사/검증 배치 원칙
- 마지막 한 번만 검사하지 않는다.
- 업로드 직후, 분석 후, 검수 후, 결과 생성 후 등 흐름 중간에 분산 배치해 점검한다.
- 검사 결과에 따라 중단/경고/재시도/안내 중 적절한 조치를 선택한다.
- 검사 실패 시 결과를 그대로 끝내지 말고 원인과 조치를 남긴다.

## 이상 발견 시 처리 원칙
- 이상이 생기면 그 데이터를 버리거나 그냥 끝내지 않는다.
- 이상이 있으면 해당 데이터/항목을 검수/분류 단계로 넘겨서 처리할 수 있게 연결한다.
- 즉, 검증에서 나온 이상도 결국 검수 대상으로 이어서 다룰 수 있게 남긴다.
- 단, 파일 자체를 읽을 수 없거나 접수 자체가 성립하지 않는 수준의 이상은 즉시 안내/재시도 필요 항목으로 남긴다.

## 출력
- 검사 결과
- 이상 항목
- 실패/이상 원인
- 상태 요약
- 재시도/안내 필요 여부
- 필요 시 검수 단계로 넘길 대상 정보

## 산출물
- 단계별 검사 결과
- 이상 항목 목록
- 상태 요약
- 재시도/안내 필요 여부
- 검수 연결 대상(필요 시)

## 실행 조건
- 검사할 단계 결과 또는 최종 결과가 있어야 한다.
- 파일 정보, 파일 상태, 분석 결과, 검수 결과, 최종 결과, 생성 시점/기준 정보를 받을 수 있어야 한다.
- 검사 기준은 한 번 보고 끝나는 방식이 아니라, 반복 실행해도 같은 기준으로 체크할 수 있게 정리한다.

## 결과 전달 방식
- 이 스킬의 검사 결과는 중간 단계에서 사용자에게 따로 노출되지 않고, 최종 결과에 포함된다.
- 이상이 있으면 최종 결과에 이상 항목, 실패/이상 원인, 상태 요약, 재시도/안내 필요 여부를 함께 보이게 한다.
- 이상이 검수/분류로 넘어가야 하는 경우, 검수 대상 정보와 함께 연결되게 남긴다.

## 재사용성
- 특정 파일/특정 월에만 맞춘 점검이 아니라, 여러 실행에서 반복해서 쓸 수 있는 검사 규칙으로 구성한다.
- 파일/분석/검수/결과/최종 각 단계의 검사 항목을 재사용 가능한 형태로 둔다.
- 새 파일 형식이나 새 열이 생겨도 검사 기준을 확장할 수 있게 한다.

## 비고
- 이 스킬의 핵심은 “문제가 있으면 끝”이 아니라 “문제가 있으면 원인을 남기고 다음 처리로 넘김”이다.
- 특히 이번 흐름에서는 검증 이상을 검수/분류와 연결해, 사람이 확인·확정할 수 있게 이어지는 구조를 중요하게 본다.
- 검증 기준은 자동 검사만으로도 확인하고, 필요하면 사람이 최종 확인할 수 있게 남긴다.

## 범위

### 처리하는 것
- `SPEC.md` §6이 정의한 6개 지점에서 단계별 자동 검사
- 이상 항목, 원인, 상태 요약, 재시도/안내 필요 여부 기록
- 이상 항목의 검수/분류 단계 연결

### 처리하지 않는 것
- **데이터 수정, 값 보정, 이상 항목 삭제** → 하지 않는다. 기록하고 넘긴다
- **문제 유형 판정과 처리 방향 결정** → classify-skill. verify는 "이상이 있다"까지, classify는 "어떤 문제이고 어떻게 처리할지"
- **이상 발견 시 무조건 중단.** 접수 자체가 성립하지 않는 경우만 중단하고, 나머지는 흐름을 이어가며 기록한다
- **검사 결과 은닉.** 통과/실패 모두 최종 결과에 포함한다

### 검사 지점
`after_file_input`, `after_analyze`, `after_classify`, `after_query_export`, `after_calendar_chatbot`, `after_final_result`

## 예시

### 입력
각 단계 종료 시점의 결과 + 이전 단계 검사 결과

### 출력 (전 지점 검사 결과 — 869건 실행 기준)

| 지점 | 검사 항목 | 결과 | 비고 |
|---|---|---|---|
| after_file_input | 파일 존재/읽힘 | 통과 | 4/4 |
| after_file_input | 필수 열 존재 | 통과 | 매핑표 4종 전부 일치 |
| after_file_input | 중복 접수 | 통과 | 해시 중복 0건 |
| after_analyze | `추가 + 스킵 = 데이터행 수` | 통과 | 869 + 0 = 869 |
| after_analyze | 금액 비숫자/누락 | **이상 1건** | 2026-01 원천세 `amount: null` |
| after_analyze | 프로젝트 미매칭 비율 | **경고** | 미매칭 7건 + 인명 의심 2그룹 |
| after_analyze | 월별 집계 합계 정합 | 통과 | 프로젝트별 합 = 월별 합 |
| after_analyze | 분류 보류 비율 | **경고** | `use` 공백 709/869 = 81.6% |
| after_classify | 배정 누락/중복 | 통과 | 합이 869와 일치(분할값 808/57/4는 형식 예시) |
| after_classify | 동일 유형 반복 미규칙화 | **경고** | `use` 공백 709건이 단일 유형 |
| after_query_export | 기준 월 vs 반영 데이터 | 통과 | 2026-05 |
| after_query_export | 조회 결과 공백 사유 구분 | 통과 | 2026-02 매출 0 사유 기록됨 |
| after_calendar_chatbot | 캘린더-분석 결과 연결 | 통과 | 회수 합계 = 매출 합계 |
| after_final_result | 8개 항목 누락 | 통과 | 8/8 |
| after_final_result | 이전 이상의 최종 반영 | 통과 | 이상 1 + 경고 3 모두 포함 |

### 출력 (이상 항목 상세)

```
[이상] 금액 누락 1건
  대상: 2026-01-31 원천세 / 지방세 / 2026년 01월 특별징수
  원인: 원본 파일의 총납부세액 셀이 비어 있음
  조치: 0으로 채우지 않고 amount: null로 보존. classify로 연결해 사람 확인 대상으로 분리
  재시도 필요: 아니오 (원본 확인 필요)
  검수 연결: 예

[경고] 분류 보류 과다 81.6%
  대상: 간이영수증 709건 (use 열 공백)
  원인: 원본 데이터 자체에 용도가 입력되지 않음. 파싱 오류가 아님
  조치: place(사용처) 문자열 기반 규칙 분류로 처리하고, 실패분만 검수로 넘김
  재시도 필요: 아니오
  검수 연결: 실패분에 한해 예

[경고] 프로젝트 미매칭
  대상: proj 공백 5건, 인명 의심 2그룹(차내윤/송인석)
  원인: 원본 미기재 또는 프로젝트가 아닌 값 입력
  조치: 자동 확정하지 않고 검수 목록으로 연결
  재시도 필요: 아니오
  검수 연결: 예
```

```
상태 요약: 이상 1건 / 경고 3건 / 통과 11건
재시도 필요: 없음
안내 필요:   있음 — 검수 목록 57건 확정 후 재실행 권장
```

진행 표시: `검사 완료 — 이상 1건(금액 누락), 경고 3건`

### 접수 자체가 성립하지 않는 경우

```
입력: 매입(신규형식).xls — 헤더행에 매핑표 열 이름이 없음
출력:
  [이상] 필수 열 없음 / 재시도 필요: 예 / 검수 연결: 아니오
  원인: state-schema.md §3 매핑표에 등록되지 않은 열 구성
  조치: 흐름 중단. 열 이름 추측 보완은 하지 않는다.
        매핑표에 행을 추가하거나 원본 형식을 확인한 뒤 재업로드 필요
```

## 성공 기준

- [ ] 6개 지점 전부에서 검사가 실행되고, 지점별 결과가 남는다
- [ ] `추가 + 스킵 = 데이터행 수` 검사가 실행되고 869 + 0 = 869로 통과한다
- [ ] 2026-01 원천세 금액 누락 1건이 이상으로 검출된다
- [ ] `use` 공백 709건이 파싱 오류가 아니라 원본 특성임을 원인에 명시한다
- [ ] 2026-02 매출 0이 이상으로 오검출되지 않는다
- [ ] 모든 이상/경고에 대상 / 원인 / 조치 / 재시도 필요 / 검수 연결 5개 항목이 있다
- [ ] 통과 항목도 최종 결과에 포함된다(이상만 보고하지 않는다)
- [ ] 필수 열 누락 시에만 흐름을 중단하고, 나머지 이상은 흐름을 이어간다
- [ ] 같은 입력으로 재실행했을 때 동일한 검사 결과가 나온다
- [ ] verify가 어떤 데이터도 수정하지 않았다
