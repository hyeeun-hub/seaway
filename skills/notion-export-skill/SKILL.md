# notion-export-skill

## 목적
final-assembly가 정리한 최종 결과 요약을, 고정된 노션 페이지("씨웨이테크 대시보드") 하나에 항상 최신 상태로 반영한다.
원칙적으로 새 페이지나 새 데이터베이스 row를 만들지 않고, 매 실행마다 같은 페이지의 본문 전체를 덮어쓴다.
단, 고정 페이지를 검색으로 찾지 못하는 상황(삭제·이름 변경 등)에 대비해 재검색 1회 → 그래도 못 찾으면 새 페이지 생성이라는 예외 경로를 둔다(§처리 3~4).
`out/` 웹 결과물 HTML이 "매번 새 파일로 쌓이는" 방식인 것과 반대로, 이 스킬은 "페이지 하나를 계속 최신 상태로 유지"하는 방식이다.

## 언제 실행하나
- final-assembly가 최종 결과(8개 항목 요약)를 만든 직후 실행한다.
- 흐름의 맨 마지막 연결이며, 이후 다음 스킬로 결과를 넘기지 않는다.

## 입력
- final-assembly 최종 결과 요약값(총 거래 수, 매출/매입/손익 합계, 월별 손익, 검수 현황 등 — 화면에 표시한 값과 동일한 수준)
- 생성 시점, 기준 정보(누적 거래 기준 집계 여부 등)
- 고정 페이지 식별 정보: 검색 대상 페이지 제목 `씨웨이테크 대시보드`, 재생성 시 페이지 제목 `씨웨이테크 대시보드 재생성`

## 처리
1. `composio_execute({ tool: "NOTION_SEARCH_NOTION_PAGE", args: { query: "씨웨이테크 대시보드" } })`로 고정 페이지를 검색해 페이지 ID를 얻는다(1차 검색).
2. 1차 검색이 0건이면, 동일한 조건으로 **한 번만 더** 검색한다(2차 검색, 일시적 지연/오류 대응).
3. 2차 검색도 0건이면, 새 페이지를 생성한다.
   - tool: `NOTION_CREATE_NOTION_PAGE`(가정값. **정확한 Composio tool 이름은 실제 연결 시 확인 필요**)
   - 제목: `씨웨이테크 대시보드 재생성` (원본 고정 페이지 제목 `씨웨이테크 대시보드`와 다르게 붙여, 예외적으로 새로 만든 페이지임을 제목만 보고도 구분할 수 있게 한다)
   - 상위 위치: 기존 고정 페이지가 있던 자리와 같은 상위 페이지(예: `혜은 강의 Notion HQ`) 아래
   - 생성 성공 시 그 페이지 ID를 이후 단계에서 그대로 쓴다
4. 검색(1차 또는 2차) 결과가 **2건 이상**(동일 제목 페이지 복수)이면, 재검색·생성으로 넘어가지 않는다. 모호성은 재시도로 해결되지 않으므로 즉시 멈추고 이상 항목으로 남긴다.
5. 이렇게 확보한 페이지 ID(검색으로 찾은 기존 페이지 또는 새로 만든 페이지)에 `composio_execute({ tool: "NOTION_REPLACE_PAGE_CONTENT", args: { page_id: <id>, content: <본문> } })`로 본문 전체를 최신 요약으로 덮어쓴다.
6. 본문에는 화면(웹 결과물 HTML의 `window.DASHBOARD_DATA`, `workflow.md` §7-4)에 표시한 값과 동일한 요약 수준만 담는다. 원본 거래 내역은 넣지 않는다.
7. 성공/실패, 새 페이지 생성 여부, 시점을 기록한다.

## 출력
- 동기화 상태(성공/실패)
- 갱신된 페이지 제목/ID
- 새 페이지 생성 여부(`page_created`: true/false)
- 동기화 시점
- 실패 시 이상 항목(원인, 재시도 필요 여부)

## 산출물
- 노션 페이지 갱신 결과(성공/실패, 신규 생성 여부 포함)
- 실패 시 이상 항목

## 실행 조건
- final-assembly 최종 결과가 있어야 실행한다.
- 고정 페이지가 검색으로 정확히 1건 확인되거나, 재검색까지 실패한 뒤 새로 생성된 페이지가 있어야 실행을 계속한다.
- 동일 제목 페이지가 2건 이상 매칭되면 재검색·생성 없이 즉시 멈춘다.

## 결과 전달 방식
- 이 스킬은 흐름의 마지막이라 다음 단계로 결과를 넘기지 않는다.
- 사용자에게는 진행 표시 1~2줄만 보인다(`SPEC.md` §3).
- 동기화 실패는 즉시 표시 예외 대상이다. 최종 결과 화면에도 함께 남는다.

## 재사용성
- 검색 쿼리(페이지 제목)를 바꾸면 다른 고정 페이지로도 재사용할 수 있다.
- 다만 "페이지 하나를 계속 덮어쓴다"는 방식 자체는 바꾸지 않는다. 로그를 쌓고 싶다면 이 스킬이 아니라 별도 스킬로 설계해야 한다.

## 비고
- 이 스킬은 노션 안에 실행 이력을 쌓는 로그가 아니라, 하나의 대시보드 페이지를 최신 상태로 유지하는 역할이다.
- `NOTION_REPLACE_PAGE_CONTENT`는 페이지 본문을 전체 교체하므로, 이전 실행 시점의 내용은 노션 안에 따로 남지 않는다.

## 범위

### 처리하는 것
- 고정 페이지 검색(`NOTION_SEARCH_NOTION_PAGE`), 0건 시 동일 조건 재검색 1회
- 재검색까지 0건일 때 새 페이지 생성(예외 경로, §처리 3)
- 페이지 본문 전체 덮어쓰기(`NOTION_REPLACE_PAGE_CONTENT`)
- final-assembly 요약값을 노션 본문 형식으로 변환

### 처리하지 않는 것
- **검색 없이 곧바로 새 페이지 생성** → 하지 않는다. 1차·2차 검색을 모두 시도한 뒤에만 생성한다
- **동일 제목 페이지가 2건 이상일 때 자동 선택 또는 추가 생성** → 하지 않는다. 모호성은 재시도·생성으로 해결하지 않고 즉시 이상으로 남긴다
- **원본 거래 상세 업로드** → 하지 않는다. `SPEC.md` §3 결과 노출 정책과 동일하게 요약 수준만 올린다
- **페이지의 특정 블록만 부분 수정** → 하지 않는다. `NOTION_REPLACE_PAGE_CONTENT`는 전체 교체만 지원한다
- **노션 인증/Composio 커넥터 연결 설정** → 플랫폼(TimelyAI) 쪽에서 이미 연결해둔 상태를 전제로 한다. 이 스킬의 책임이 아니다

### 제약
- `NOTION_REPLACE_PAGE_CONTENT`는 페이지 전체를 교체하므로, 이전 실행 내용은 노션 안에 남지 않는다(알려진 한계)
- 재검색은 동일 조건으로 1회만 한다. 그 이상 반복 검색하지 않는다
- 새 페이지 생성 도구 이름(`NOTION_CREATE_NOTION_PAGE`)은 가정값이다. 실제 Composio notion 툴킷에 등록된 정확한 이름으로 실행 전 확인해야 한다
- 새로 만든 페이지 제목은 의도적으로 `씨웨이테크 대시보드 재생성`으로 원본과 다르게 붙인다. 검색 쿼리(`씨웨이테크 대시보드`)가 이 제목에도 부분 일치로 걸릴 가능성이 높지만, Composio notion 검색이 정확히 어떤 매칭 방식을 쓰는지는 실제 연결 전까지 확정할 수 없다. 부분 일치가 안 되면 다음 실행에서도 이 페이지가 검색되지 않아 또 새 페이지가 생길 수 있다(알려진 한계, 실제 검색 동작 확인 필요)
- 검색 결과가 2건 이상이면 아무거나 골라 덮어쓰지 않는다. 이상으로 남기고 verify로 연결한다
- 화면에 없는 값을 노션 본문에 추가하지 않고, 화면에 있는 값을 빠뜨리지 않는다

## 예시

### 입력
```
final-assembly 최종 결과 요약
  기준: 누적 거래 기준 집계, 869건
  매출 553,180,106 / 매입·경비 493,177,179 / 손익 60,002,927
  월별 손익: 2026-01 +33,196,357 / 02 -92,578,174 / 03 +75,051,609 / 04 -39,731,296 / 05 +84,064,431
  검수: 자동 처리 808건 / 확인 필요 57건 / 보류 4건 (형식 예시값)
고정 페이지: "혜은 강의 Notion HQ / 씨웨이테크 대시보드"
```

### 처리
```
1) composio_execute({ tool: "NOTION_SEARCH_NOTION_PAGE", args: { query: "씨웨이테크 대시보드" } })
   → page_id: <검색된 페이지 ID> 1건 매칭

2) composio_execute({
     tool: "NOTION_REPLACE_PAGE_CONTENT",
     args: {
       page_id: "<검색된 페이지 ID>",
       content:
         "씨웨이테크 대시보드\n\n" +
         "생성 시점: 2026-08-06T19:07:21+09:00\n" +
         "기준: 누적 거래 기준 집계\n\n" +
         "요약\n" +
         "총 거래 수: 869\n" +
         "총 금액: 1,046,357,285\n" +
         "매출: 553,180,106\n" +
         "매입/경비: 493,177,179\n" +
         "합계 손익: +60,002,927\n\n" +
         "월별 손익\n" +
         "2026-01: +33,196,357\n" +
         "2026-02: -92,578,174\n" +
         "2026-03: +75,051,609\n" +
         "2026-04: -39,731,296\n" +
         "2026-05: +84,064,431\n\n" +
         "검수 필요: 57건 (검수 목록으로 이동)\n"
     }
   })
   → 성공
```

### 출력
```
동기화 완료 — 씨웨이테크 대시보드 갱신, 869건 기준
```

진행 표시: `노션 동기화 완료 — 씨웨이테크 대시보드 갱신` (`SPEC.md` §3)

### 재검색까지 실패해서 새 페이지를 만든 경우
```
1차: composio_execute({ tool: "NOTION_SEARCH_NOTION_PAGE", args: { query: "씨웨이테크 대시보드" } })
  → 0건 매칭
2차(재검색): composio_execute({ tool: "NOTION_SEARCH_NOTION_PAGE", args: { query: "씨웨이테크 대시보드" } })
  → 0건 매칭
생성: composio_execute({
    tool: "NOTION_CREATE_NOTION_PAGE",   ※ 가정값, 실제 tool 이름 확인 필요
    args: { title: "씨웨이테크 대시보드 재생성", parent: "혜은 강의 Notion HQ" }
  })
  → page_id: <새로 생성된 페이지 ID>
이어서: composio_execute({ tool: "NOTION_REPLACE_PAGE_CONTENT", args: { page_id: "<새 ID>", content: <본문> } })
  → 성공

출력:
  동기화 완료 — 새 페이지 생성 후 갱신 (page_created: true)
```

진행 표시: `노션 동기화 완료 — 새 페이지 생성 후 갱신` (`SPEC.md` §3)

### 동일 제목 페이지가 2건 이상 매칭된 경우
```
composio_execute({ tool: "NOTION_SEARCH_NOTION_PAGE", args: { query: "씨웨이테크 대시보드" } })
  → 2건 매칭
출력:
  [이상] 고정 페이지 중복 / 재시도 필요: 아니오(재검색으로 해결 안 됨) / 검수 연결: 아니오
  원인: 동일 제목 페이지가 2건 이상 존재해 어느 것이 고정 페이지인지 판단 불가
  조치: 자동으로 고르거나 새로 만들지 않는다. 중복 페이지를 정리한 뒤 재실행 필요
```

## 성공 기준

- [ ] 정상 실행(1건 매칭) 시 검색으로 찾은 페이지 ID에만 덮어쓰기가 수행된다
- [ ] 1차 검색이 0건이면 동일 조건으로 2차 검색이 정확히 한 번 더 실행된다
- [ ] 2차 검색도 0건이면 새 페이지가 생성되고, 그 페이지에 본문이 채워진다(`page_created: true`)
- [ ] 동일 제목이 2건 이상 매칭되면 재검색·생성 없이 즉시 중단하고 이상 항목으로 남긴다
- [ ] 덮어쓴/새로 채운 본문에 원본 거래 상세가 없고, 요약 수준 값만 있다
- [ ] 화면(HTML `window.DASHBOARD_DATA`)에 있는 값과 노션 본문의 값이 일치한다
- [ ] 동일 입력으로 재실행해도 같은 본문으로 덮어써진다(재현 가능)
- [ ] 노션에는 직전 실행 내용만 남고, 이전 실행 이력은 남지 않는다는 한계가 문서에 명시돼 있다
