# classify-skill

## 목적
analyze-skill이 만든 분석 결과에서 사람이 확인하거나 규칙 처리가 필요한 거래를 실제로 분리한다.  
거래별로 문제 유형과 처리 방법을 정리하고, 확정/제외/수정/보류 같은 처리 상태를 구분한다.  
규칙으로 딱 맞는 건 자동 처리하고, 애매한 건은 검수창에서 대표가 확인·확정할 수 있게 검수 목록으로 넘긴다.

## 언제 실행하나
- analyze-skill이 분석 결과(프로젝트별 손익, 월별 손익, 일반관리비 분류 결과, 매칭 결과, 정규화 거래 데이터 등)를 만든 뒤 실행한다.
- 분석 결과에서 확인 필요 거래, 이상 거래, 미매칭 거래가 있으면 실행한다.
- 분석 결과를 그대로 확정하지 말고, 확정 전에 걸러야 할 항목을 정리하는 단계로 실행한다.

## 입력
- 분석된 거래 데이터
- 프로젝트 매칭 결과
- 금액/날짜/프로젝트 이상 정보
- 분석 시점/기준 파일 정보
- 규칙 처리 기준(자동 확정/제외/수정에 쓸 규칙)
- 필요 시 이전 검수 결과나 확정 이력

## 처리
- 분석 결과에서 확인 필요 거래를 분리한다.
  - 프로젝트/현장이 비어 있거나 매칭되지 않은 거래
  - 금액이 비정상적이거나 형식이 이상한 거래
  - 날짜 표기나 기간 판단이 애매한 거래
  - 용도/계정 성격이 규칙상 자동 분류되기 어려운 거래
  - 같은 내용이 여러 건인데 처리 방식이 충돌할 수 있는 거래
- 거래별로 문제 유형을 정리한다.
  - 미매칭
  - 금액 이상 의심
  - 날짜/기간 이상 의심
  - 분류 애매
  - 중복 의심
  - 내용 충돌/확인 필요
- 거래별로 처리 방법을 정리한다.
  - 규칙 자동 확정
  - 규칙 자동 제외
  - 규칙 자동 수정
  - 사람 확인 필요
- 규칙 처리는 “딱 맞는 경우만” 자동으로 처리한다.
  - 조건이 명확하고 재실행해도 같은 결과가 나오는 건 자동 처리
  - 애매하면 자동 처리하지 않고 검수 목록으로 넘김
- 자동 처리한 결과도 나중에 확인 가능하게 남긴다.
- 사람 확인이 필요한 건은 검수 대상 목록으로 정리한다.
  - 어떤 거래를
  - 왜 확인 필요로 봤는지
  - 어떻게 처리하면 되는지
  - 확정/제외/수정 중 어느 방향인지
  를 함께 남긴다.
- 검수 필요 목록이 나오면 검수 목록으로 이동했다고 표시한다.

## 출력
- 검수 대상 목록
- 거래별 문제 유형
- 처리 방법
- 확정/제외/수정/보류 결과
- 규칙 처리 항목 결과
- 자동 처리 결과와 사람 확인 필요 결과의 구분
- 검수 목록 이동 표시

## 산출물
- 검수 대상 목록
- 거래별 문제 유형 및 처리 방법
- 확정/제외/수정/보류 구분 결과
- 규칙 처리 결과

## 실행 조건
- 분석 결과가 있어야 실행한다.
- 규칙 기준이 있으면 자동 처리 범위를 더 분명하게 정할 수 있다.
- 규칙이 애매한 건은 억지로 확정하지 말고 검수 목록으로 넘긴다.
- 확정/제외/수정 결과는 이후 결과 생성/조회, 캘린더/챗봇/요약, 자동 검사/검증이 참고할 수 있게 남긴다.

## 결과 전달 방식
- 이 스킬의 결과는 다음 단계로 자동으로 넘겨진다.
- 사용자는 중간 검수 과정을 따로 보지 않고, 최종 결과에서 검수 대상과 처리 방향을 확인할 수 있게 한다.
- 검수 필요 목록이 있으면 검수 목록으로 이동했다고 표시하고, 이후 사용자가 그 목록으로 가서 확인/확정할 수 있게 연결한다.

## 재사용성
- 특정 파일 하나에만 맞춘 검수가 아니라, 여러 ERP 분석 결과에 공통으로 적용 가능한 분류/검수 분리 로직으로 쓴다.
- 문제 유형, 처리 방법, 자동 규칙, 사람 확인 대상 구분을 재사용 가능한 형태로 남긴다.
- 규칙이 늘어나면 같은 구조로 추가 처리할 수 있게 한다.

## 비고
- 이 스킬의 핵심은 “전부 자동 확정”이 아니라 “딱 맞는 건 자동, 애매하면 사람”이다.
- 검수 목록 이동 표시는 단순 알림이 아니라, 어떤 건이 왜 넘어갔고 어디로 가면 되는지까지 이어지게 한다.
- 검증 단계에서 이상 소견이 나오면 그 데이터/항목은 이 스킬이 정리한 검수 대상과 연결되도록 남긴다.

## 범위

### 처리하는 것
- 확인 필요 거래 분리 및 문제 유형 판정
- 거래별 처리 방법(규칙 자동 확정/제외/수정, 사람 확인 필요) 배정
- 검수 대상 목록 생성 및 검수 목록 이동 표시

### 처리하지 않는 것
- **파싱, 정규화, 중복 판정, 집계** → analyze-skill
- **거래 값 실제 수정.** "수정" 판정은 방향만 기록하며, 원본 거래(`Transaction` 테이블)를 고치지 않는다
- **애매한 건의 확정.** 재실행 시 같은 결과가 보장되지 않으면 자동 처리하지 않는다
- **사람 대신 최종 승인.** 검수창에서 대표가 확정한다

### 자동 처리 허용 조건
아래 3개를 **모두** 만족할 때만 자동 처리한다.
1. 판정 조건이 값 비교만으로 표현된다(문맥 추론 불필요)
2. 같은 입력에 대해 항상 같은 결과가 나온다
3. 오판정 시 verify가 잡을 수 있는 흔적이 남는다

## 예시

### 입력
analyze-skill 출력(869건 정규화 거래 + 매칭 결과 + 이상/주의 항목)

### 출력 (문제 유형별 집계)

| 문제 유형 | 건수 | 처리 방법 | 근거 |
|---|---:|---|---|
| 분류 애매(`use` 공백) | 709 | 규칙 자동 분류 시도 → 실패분만 사람 확인 | 간이영수증 `use`/`content` 전량 공백. `place` 문자열로 판정 |
| 미매칭(`proj` 인명 의심) | 2건 그룹 | 사람 확인 필요 | `차내윤`, `송인석` |
| 미매칭(`proj` 공백) | 5 | 사람 확인 필요 | 간이영수증 5건 |
| 금액 누락 | 1 | 사람 확인 필요 | 2026-01 원천세 `amount: null` |
| 프로젝트 아님(일반관리비) | 8건 그룹 | 규칙 자동 확정 | `사무실운영`, `공장운영`, `연구전담부서` 등 사전 등록 목록 일치 |
| 매출 없는 매입 프로젝트 | 4 | 보류 | `2025년 추자면 대서리 부잔교` 등. 기간 밖 매출로 추정 |
| 통과거래 의심 | 1 | 규칙 자동 확정 + 표기 | `창조이엔지` 매출=매입, 손익 0 |

### 출력 (검수 대상 목록 — 대표 예시)

| # | 거래 | 문제 유형 | 처리 방법 | 방향 |
|---|---|---|---|---|
| 1 | 2026-01-31 원천세 지방세 / `amount: null` | 금액 누락 | 사람 확인 필요 | 원본 확인 후 **수정** 또는 **제외** |
| 2 | `proj = 차내윤` 매입 164,520원 | 미매칭(인명 의심) | 사람 확인 필요 | 개인경비면 **제외**, 현장이면 **수정** |
| 3 | `proj = 송인석` 매입 1,597,194원 | 미매칭(인명 의심) | 사람 확인 필요 | 위와 동일 |
| 4 | `proj` 공백 간이영수증 5건 4,664,910원 | 미매칭(공백) | 사람 확인 필요 | 현장 지정 후 **수정** |
| 5 | `2025년 추자면 대서리 부잔교` 매입 77,512,024원 / 매출 0 | 매출 없는 매입 | 보류 | 2025년 매출 데이터 추가 업로드 필요 |

```
자동 처리: 808건   사람 확인 필요: 57건   보류: 4건   (808 + 57 + 4 = 869)
※ 808 / 57 / 4는 형식 예시값이며 실측 수치가 아니다. 아래 주의 참조.
→ 검수 목록으로 이동했습니다 (57건)
```

진행 표시: `검수 분류 완료 — 자동 처리 808건 / 확인 필요 57건`

> **주의 — 실측값과 예시값의 구분**
> 위 808 / 57 / 4는 **분류 규칙을 확정한 뒤에야 나오는 값이며, 아직 실측되지 않았다.** 출력 형식 예시로만 쓴다.
> 실데이터로 확정된 수치는 문제 유형 표의 709(`use` 공백) / 5(`proj` 공백) / 1(금액 누락) / 8(일반관리비 그룹) / 4(매출 없는 매입 프로젝트)와 총계 869건이다.
> 따라서 성공 기준은 특정 분할값이 아니라 **세 건수의 합이 869와 일치하는지**로 검증한다.

### 자동 처리 vs 사람 확인 판정 예

```
입력: proj = "사무실운영",  place = "웹케시(주)",  amount = 59400
→ 규칙 자동 확정. 사전 등록 일반관리비 목록에 "사무실운영" 정확히 일치.
   조건이 값 비교만이고 재실행 시 동일 → 자동 처리 허용 3조건 충족

입력: proj = "차내윤",  place = "(주)대성",  use = "복리후생비",  amount = 18050
→ 사람 확인 필요. "인명처럼 보인다"는 문맥 추론이며 값 비교로 표현되지 않음.
   자동 처리 허용 조건 1 위반 → 검수 목록으로 이동
```

## 성공 기준

- [ ] 869건 전량이 자동 처리 / 사람 확인 필요 / 보류 중 정확히 하나로 분류되고, 세 건수의 합이 869와 일치한다
- [ ] 2026-01 원천세 금액 누락 1건이 사람 확인 필요로 분리된다
- [ ] `차내윤`, `송인석`이 자동 확정되지 않고 검수 목록에 오른다
- [ ] `사무실운영` 등 사전 등록 일반관리비 값은 사람 확인 없이 자동 확정된다
- [ ] 검수 대상 각 건에 거래 / 문제 유형 / 처리 방법 / 방향 4개 항목이 모두 있다
- [ ] 검수 필요 건이 1건 이상이면 "검수 목록으로 이동" 표시와 대표 예시가 함께 출력된다
- [ ] 같은 입력으로 재실행했을 때 자동 처리 건수와 배정 결과가 동일하다
- [ ] 원본 거래(`Transaction` 테이블)가 수정되지 않았다
