# ERP Flow

**ERP가 못 보여주는 진짜 이익을 찾는다.**

건설·해양구조물 시공사의 ERP 엑셀(매출·매입·경비·급여·대출·자산)을 한 번에 올리면,
파싱부터 중복 제거·프로젝트별 손익·일반관리비 분류·검수·회수 캘린더·자동 검증까지 이어서
처리하고, 마지막에 **인건비·이자·감가상각까지 반영한 손익**을 보여준다.

씨웨이테크 실제 ERP 데이터로 검증했다. 변동비 기준으로는 **7,207만원 흑자**인데,
파생원가를 반영하면 **2,208만원 적자**로 뒤집힌다. 이 프로젝트는 그 차이가 어디서
생기는지를 클릭해서 원본 거래까지 내려가며 확인할 수 있게 만든 것이다.

## 바로 돌려보기

Node 20 이상과 인터넷 연결이 필요하다.

```bash
cd webapp
npm install                              # postinstall이 prisma generate까지 실행
cp .env.example .env
npx create-db@latest --env .env          # 임시 Postgres 발급 (DATABASE_URL 자동 기입)
npx prisma migrate deploy && npx prisma db seed
npm run dev
```

브라우저에서 `data/`의 엑셀 9개를 업로드하면 전체 파이프라인이 재현된다.
`GEMINI_API_KEY`를 넣으면 챗봇도 활성화된다(비워두면 챗봇만 비활성, 나머지는 정상).

테스트는 `npm test`(26개), 프로덕션 빌드 확인은 `npm run build`.

## 설계에서 신경 쓴 것

**같은 거래를 두 번 넣지 않는다 — 2단 방어**
파일 해시로 1차, 거래 식별자 `(tx_key, seq)`로 2차. `seq`는 필수다 — 출장자 3명분 항공권처럼
모든 필드가 동일한 정상 거래가 실제로 존재하기 때문에, 순번이 없으면 정상 반복이 중복으로
삼켜진다. 파일명은 키에 넣지 않는다(재추출로 이름이 바뀌면 중복 제외가 깨진다).

**딱 맞는 것만 자동, 애매하면 사람에게**
자동 확정은 (1) 값 비교만으로 판정되고 (2) 재실행해도 같은 결과이며 (3) 틀리면 검증이 잡을 수
있는 경우로 한정한다. 문맥 추론은 규칙화하지 않고 검수로 넘긴다.

**모르는 값은 채우지 않는다**
금액 셀이 비면 `0`이 아니라 `null`로 남기고 검수로 보낸다. 연이율이 없는 대출은 이자 계산에서
제외하고 "계산 불가"로 표시한다. 원본에 계정과목이 적혀 있으면 추론하지 않고 그대로 옮겨 쓴다.

**금액을 만드는 경로에 LLM이 없다**
챗봇은 화면에 이미 표시된 요약 숫자만 읽고 답한다. 계산·분류·집계는 전부 코드와 규칙이 한다.
LLM 제안은 사람이 볼 힌트일 뿐 확정 근거가 아니다.

**검증을 흐름 중간에 분산한다**
접수 후 · 분석 후 · 분류 후 · 조회 후 · 캘린더 후 5개 지점에서 자동 검사가 돌고, 결과를 숨기지
않는다. 프로젝트 합계와 전사 합계가 원 단위로 일치하는지를 `BigInt` 항등식으로 매번 검산한다.

## 알려진 제약

정직하게 적어둔다. 전부 인지하고 있고, 후속 작업으로 잡혀 있다.

- **부가세 미처리** — 매출·매입 금액이 `합계금액`(부가세 포함) 기준이다. 공급가액 기준으로
  바꾸면 매출이 약 5,029만원 줄고 적자폭은 더 커진다. 결론의 방향은 같지만 숫자는 조정이 필요하다.
- **인증 없음** — 접근 제어가 없다. 실제 업무 투입 전에 사용자별 인증이 필요하다.
- **매입 세금계산서 일부 미분류** — 원본 `용도`가 `"매입"`으로만 적힌 건(금액 기준 72%)은
  추측하지 않고 미분류로 남겼다. 그 금액의 90.8%가 공급자 10곳에 집중돼 있어, 해당 거래처의
  계정과목만 확인되면 규칙 10개로 분류된다.
- **집계 성능** — 현재 거래 882건 규모에서는 문제없지만, 화면마다 거래 테이블 전체를 메모리로
  로드한다. 수만 건 규모에서는 SQL 집계로 내려야 한다.
- **원가율 해석 주의** — 매출과 원가의 발생 시점이 어긋나 있어(수익비용대응), 과거 원가율로
  미래를 예측하지 않는다. 수주 판단은 회계 항등식(계약금액 − 배부 고정비)으로 역산한다.
